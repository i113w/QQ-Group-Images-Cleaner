# QQ 图片清理器

按月份浏览腾讯 QQ 桌面端的群聊图片缓存，核对文件清单后移入 Windows 回收站。再次打开同一文件夹时，程序先读取本地索引，再更新新增或变化的文件。

![主界面](assets/ui-main.png)

## 使用

需要 Windows 10/11、Python 3.12+ 和 Pillow。

```powershell
python -m pip install -r requirements.txt
python qq_group_images_cleaner.py
```

点击“自动定位”查找文档目录下的 `Tencent Files/<QQ号>/Image/Group2`，也可以手动选择修改过存储位置的文件夹。只有一个 QQ 目录时会直接定位；多个目录时可输入 QQ 号。

首次选择会建立索引。以后启动时自动打开上次的文件夹，优先显示保存的统计和文件列表。

- **月份概览**：双击月份，分页查看图片。
- **文件索引**：按文件名或完整路径搜索，按月份筛选，查看时间和大小；可切换“仅图片”。
- **图片选择**：点击勾选、左键拖拽框选、右键拖拽取消选择。全选当前页的选择会保留到其他页。
- **更新索引**：检查变更；无变化时不重新枚举每个文件。
- **重新核验**：完整重新读取元数据，适用于离线修改过已有文件或结果不一致的情况。
- **停止更新**：取消当前读取，保留上一次完整索引。
- **按时间清理**：先生成完整文件清单，再确认移入回收站。

`F5` 更新索引，`Ctrl+F` 聚焦搜索。语言菜单可切换中文和英文。

![文件索引](assets/ui-index.png)

## 索引机制

索引使用 SQLite，保存文件路径、大小、时间、月份统计和目录状态。文件路径在数据库内按根目录保存为相对路径，界面和清理清单展示完整绝对路径。

首次采集通过 Windows `GetFileInformationByHandleEx` 一次读取多条目录记录，取得文件大小及创建、修改、访问时间，减少逐文件查询。目录任务使用有界队列并行处理。

程序运行期间通过 `ReadDirectoryChangesW` 捕获新增、修改、重命名和移出事件，只更新相关记录。能够读取已有 NTFS USN 日志时，还会补齐关闭程序期间的变更；日志失效或通知溢出时才重建完整基线。

**无需 Everything SDK，也不会创建或重置 NTFS 日志。** 普通权限下仍可批量采集和跟踪运行期间的文件变化。无法读取 USN 日志时，离线检查以目录变化为依据；关闭程序期间只修改已有文件内容，可能需要点击“重新核验”才能刷新其大小和时间。

索引和设置默认保存到程序旁的 `.qq-cleaner/`。该目录不可写时使用用户本地应用数据目录。需要指定位置时可使用：

```powershell
python qq_group_images_cleaner.py --folder "D:\QQ\Image\Group2" --state-dir "D:\QQCleanerState"
```

不同文件夹有独立索引。数据库格式升级时保留旧数据库。程序不清理索引缓存文件；请勿把应用索引目录选为图片目录。

## 清理规则

日期清理会从索引中筛出候选文件，再依据当前文件时间复核。文件时间沿用原项目的规则，取创建、修改和访问时间中最早的一个；它是文件元数据的估计时间。

索引与日期清理覆盖所选目录内的普通文件，**包括非图片文件**。图片浏览器只展示可识别扩展名的图片，“仅图片”是文件列表的显示筛选。

确认窗口显示来源文件夹、原因、文件数量、当前时间、大小和完整路径，也可打开完整 JSON 清单。确认前核验文件身份和路径，拒绝越界路径、符号链接、目录联接和目录目标。文件在核对后发生变化时，要求重新生成并确认清单。

清理仅使用 Windows 回收站。回收站关闭、容量无法核验、容量不足或系统拒绝回收时停止；程序没有永久删除入口或永久删除回退。移入回收站不会立即释放磁盘空间，可从 Windows 回收站还原。

## 性能记录

2026-10-27，本机普通权限、NTFS、263,140 个零字节测试文件，分布于 275 个目录：

| 项目 | 耗时 |
| --- | ---: |
| 原扫描算法读取元数据 | 1.21 秒 |
| Windows 批量枚举元数据 | 1.40 秒 |
| 首次建立并保存索引 | 5.57 秒 |
| 读取已保存的月份统计，中位数 | 1.38 毫秒 |
| 读取 50 条文件列表，中位数 | 1.93 毫秒 |
| 无变化的目录增量检查 | 28.54 毫秒 |
| 增量加入 1 个文件，仅写入 1 条记录 | 18.68 毫秒 |

统计按月份的数量和总大小与原算法一致，SQLite 完整性检查通过。另对真实 QQ 缓存样本的 95 个文件进行了只读核对，统计一致。

这些测试未清空操作系统文件缓存，零字节样本只测元数据和索引，不测图片解码。没有进行 Everything 的同条件对照，因此这些结果不构成与 Everything 相同吞吐的承诺。

## 验证与结构

```powershell
python -B -m unittest discover -s tests -v
```

32 项回归检查覆盖缓存读取、增量新增和重命名、通知溢出、USN 日志失效、取消回滚、不可读目录、时间统计、路径与文件身份、容量拦截、回收保护回调和弹窗中的异步结果。

测试只创建自己的数据，使用核验过路径的重命名模拟文件移出，保留测试文件；不调用真实回收执行。图形界面另验证了搜索、空状态、中英文、分页全选、清理清单取消和异步缩略图。截图中的图片是生成的测试样例。

| 模块 | 作用 |
| --- | --- |
| `lib/windows_native.py` | Windows 批量目录读取、文件变更通知、可选 USN 日志 |
| `lib/index_store.py` | 持久化索引、分页查询、月份统计 |
| `lib/index_service.py` | 有界采集、变更合并、取消与恢复 |
| `lib/safe_recycle.py` | 具体文件计划、审批绑定、回收站保护 |
| `lib/QQCleanerApp.py` | 主界面、搜索、索引与清理工作流 |
| `lib/ThumbnailViewerWindow.py` | 分页预览、跨页选择与框选 |
| `lib/ui_dispatch.py` | 主线程回调与弹窗中的异步调度 |
| `lib/theme.py` | 淡色主题与字体 |

更多实现说明见 [索引与回收机制](docs/index-and-recycling.md)。
